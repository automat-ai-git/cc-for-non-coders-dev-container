# Продвинутое демо: мониторинг рисков SaaS-поставщиков

## Сценарий

Компания хранит клиентские и внутренние данные в пяти SaaS-сервисах. Нужно соединить локальный реестр поставщиков с актуальными данными из интернета и подготовить решение для ИБ и закупок.

## Требования

Tavily MCP должен быть подключён. Исходные критерии находятся в `risk-criteria.md`, реестр — в `suppliers.csv`.

## Основной промпт

```text
Проведи мониторинг поставщиков из suppliers.csv по правилам risk-criteria.md.

Для каждого поставщика:
1. Найди только официальные страницы: status, security/trust, privacy, DPA, incident history или release notes.
2. Проверь события за последние 90 дней: серьёзные инциденты, изменения условий обработки данных, прекращение продукта или важные ограничения.
3. Для каждого факта укажи дату события, дату публикации, прямой URL и короткую цитату не длиннее одного предложения.
4. Отделяй «не найдено» от «этого не было».
5. Рассчитай итоговый риск по локальным критериям. Не повышай риск только из-за дорогой подписки.

Сохрани supplier-risk-report.md и source-register.csv. Исходники не меняй.
```

## Что делает пример сложным

- Claude связывает внешние факты с внутренней критичностью и типом данных.
- У события и публикации могут быть разные даты.
- Отсутствие найденной DPA не доказывает, что DPA нет.
- Один и тот же инцидент нельзя считать несколько раз по статус-странице и release notes.

## Критерии хорошего результата

- каждая оценка риска объяснена локальным фактором и источником;
- нет ссылок на поисковую выдачу, агрегаторы и пересказы;
- факты без официального подтверждения вынесены в `Нужно проверить`;
- в `source-register.csv` есть `supplier`, `claim`, `event_date`, `published_at`, `url`, `checked_at`;
- рекомендации разделены на срочные действия и вопросы к следующему продлению договора.

## Усложнение

```text
Сделай второй проход как скептический проверяющий: найди выводы, которые не следуют из источников, дубли событий и случаи, где дата публикации ошибочно принята за дату инцидента. Исправь отчёт и добавь журнал изменений.
```
